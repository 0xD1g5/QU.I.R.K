Hardened dashboard operator-token config loading, outbound URL validation for the URL-fetching scanners (redirect hops are validated, and the REST fuzzer and the RabbitMQ management probe do not follow redirects), `security.trusted_targets` coverage (`include_ips`, connector host fields, dashboard jobs, schedules and scheduled runs), error and log text for URL fetches, credential references and LDAP DNs, and `quirk token` wording. `quirk serve` exits with an error when its config file exists but cannot be read, and protected API routes answer 503 in that state. Once a running `quirk serve` or `quirk scheduler` has read its config file with settings in it, a later read that finds the file missing or empty is treated as unreadable until the file is restored or the process is restarted. `quirk sensor enroll` and `quirk sensor push` require an `https://` console URL for non-loopback hosts unless `--allow-insecure-console` is given; re-enroll existing sensors that use an `http://` console.
