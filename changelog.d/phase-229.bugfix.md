Finding state and the numbers built on it now follow what scans actually observed. Detected findings are open and read as exploitable in VEX (previously in triage), and a finding that a later scan rechecks and finds fixed is closed and reads as RESOLVED in VEX; the burndown counts follow the same state, and plaintext HTTP findings can close. Fast-mode TLS findings still cannot close, because the fast scan does not run the TLS probes; scans recorded before this release still read Not Verified. Merged and per-segment scores and the burndown counts now come from the same finding set as the report. Drift notifications fire again, because the notifier now compares the two most recent scan runs instead of comparing a scan with itself, and the trend timeline shows one point per scan run instead of splitting a scan into several points or none. `quirk sensor merge` and the merge view keep every endpoint of each sensor's latest push. `SCORING_VERSION` stays 3.0 because these are input fixes, not a model change; merge-run scores stored before this release are not recomputed.
