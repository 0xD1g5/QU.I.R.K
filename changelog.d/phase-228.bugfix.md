The dashboard and the report now compute the same headline score, consequence ceilings and subscores for a scan, and the score surfaces that bypassed the finding ceilings now apply them. Scores move for these scans: report and dashboard headline scores for default scans whose mail ports refused the connection or timed out (those ports are no longer counted as plaintext or as missing STARTTLS, and Data in Motion is unassessed when no mail server answered); the dashboard headline for scans with a certificate expiring within 30 days (now MEDIUM, as in the report), and for scans whose S/MIME, AD CS, Vault, email, broker, code-signing, cloud, JWT or OpenAPI rows carry certificate data (the dashboard no longer derives TLS certificate findings for non-TLS rows, and email, broker and code-signing rows use the report's findings); and the trend, timeline, multi-sensor merge, per-segment and Compare scores, `quirk sensor merge`'s printed band and the Slack drift notification's band, which now apply the CRITICAL and HIGH consequence ceilings. `SCORING_VERSION` stays 3.0 because these are input fixes, not a model change, and merge-run scores stored before this release are not recomputed.
