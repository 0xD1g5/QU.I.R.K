Five detection paths that never fired in a real scan now do. `--inventory-code-signing` finds the code-signing certificates the TLS scan sees, because the TLS scanner now records each leaf certificate's key usages. Kerberos etype enumeration works against KDCs that require pre-authentication (the usual configuration): the probe now names a configurable principal (`connectors.kerberos_probe_principal`, default `Administrator`, replacing `nobody`) and reads the etype list the KDC returns, and a KDC that does not know that principal now produces an explicit "etypes unavailable" row instead of a false no-pre-auth row. This was proven against a protocol-faithful fake KDC and observed once against a real Samba KDC (which offered AES-256 only); Kerberos targets must be listed by FQDN, since an IP address is used as the realm and a real KDC rejects it. `--auth-*` credentials now reach the JWKS endpoint (only logged URLs are redacted), and `--auth-basic` takes `user:password`, which QUIRK encodes: a pre-encoded or colon-less value is now rejected, so operators who passed `base64(user:password)` must switch to the plain form. A scan with a bearer token that is unsigned (`alg:none` or no `alg`) now reports a CRITICAL finding, which caps the readiness score like any CRITICAL. `SCORING_VERSION` stays 3.0 because these are input fixes, not a model change.
