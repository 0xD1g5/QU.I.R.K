Sensor enrollment no longer fails for about 1 token in 64. Bearer tokens are drawn from an alphabet that includes `-`, and `quirk sensor enroll --api-token <token>` read a token starting with `-` as a new option (`argument --api-token: expected one argument`). That included the Windows installer, `install.ps1`. `quirk console enroll`, `quirk sensor enroll` and `quirk token generate`/`rotate` now never mint a token that starts with `-`, and `install.ps1` passes `--api-token=<token>` as one argument. A token minted by 5.28.2 or earlier can still start with `-`: pass it as `--api-token=<token>`.
