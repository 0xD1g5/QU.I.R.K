# QU.I.R.K. 5.11.0 — Chunked Discovery

**Released:** 2026-08-11
**Milestone:** v5.11

## What's New

QU.I.R.K. 5.11 replaces monolithic nmap discovery with a chunked, batch-based sweep so a single
failed CIDR block or overloaded segment no longer aborts an entire scan.

- **Chunked discovery core (Phase 144):** Discovery now runs nmap per-batch with failure
  isolation — a batch that errors is recorded and skipped rather than killing the run. The
  previous `_MAX_HOSTS_PER_CIDR` cap that silently truncated large ranges is relaxed.
- **Liveness pre-pass (Phase 145):** A lightweight liveness sweep runs before the full probe
  set, with a non-root privilege fallback so unprivileged operators still get a liveness signal
  instead of a hard failure. Down hosts are recorded (`up=False`) rather than silently dropped.
- **Progress, scaling & disclosure (Phase 146):** Per-batch progress and timing now scale with
  batch size instead of using a single fixed timeout for the whole scan, and hosts that could not
  be conclusively classified are disclosed as "undetermined" rather than folded into another
  status bucket.
- **Backlog drain — lifecycle & ledger tail (Phase 147):** `--resume-scan-id` continuations now
  also run OT/ICS (Modbus/BACnet) supplemental fingerprinting; the deferred-items ledger was
  re-triaged and a port-aware dashboard CORS default (`QUIRK_DASHBOARD_PORT`) was added.

## Known Issues

### Windows — No Asset Produced (PyPI-only release)

This release is **PyPI-only**. `pip install quirk-scanner==5.11.0` works; there is no
`quirk-windows-5.11.0.zip` and no Windows asset of any kind for this version.

**Why:** the `windows-package` CI job failed at the "CI self-test — ephemeral cert signing
round-trip" step, which runs *before* the Release-creation step — so no GitHub Release assets
were ever attached, and no GitHub Release object exists for this tag at all.

**Root cause:** `signtool verify /pa` applies Authenticode policy, which requires a certificate
chain terminating in a *trusted* root. A self-signed certificate placed in `Cert:\CurrentUser\My`
can never satisfy that policy. The self-test step had never actually executed before this tag —
`v5.10.0` was never pushed, and `v5.9` never matched the `v*.*.*` tag glob — so it failed on its
first real run, by construction.

**Fixed in commit `1a6effc`** (`fix(release): trust the ephemeral root so the signing self-test
can actually pass`), already on `main` — but it landed *after* the `v5.11.0` tag was pushed,
which is why the tag itself cannot produce the artifact.

**`v5.12.0` is the first version with a verified Windows artifact.**

**Operator guidance:** install from PyPI, build the Windows bundle from source using the current
`release.yml`, or upgrade to `v5.12.0` or later once it ships.

No zip was backfilled onto this tag deliberately. Attaching a binary built from a since-changed
workflow would misrepresent what this tag's own pipeline produced — a provenance risk this
project treats seriously given it ships Sigstore attestations and PyPI Trusted Publishers.
Release history stays strictly reproducible-from-tag.

## Upgrade Guidance

```bash
pip install --upgrade quirk-scanner
```

**No breaking changes.** All v5.10 configuration files, databases, and scan outputs are
forward-compatible. There is no Windows distributable change to note in this release, because
none shipped — see "Windows — No Asset Produced" above.
