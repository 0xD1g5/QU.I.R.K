# QU.I.R.K. 5.15.0 — Lifecycle Tail Drain

**Released:** 2026-08-26
**Milestone:** v5.15

## What's New

QU.I.R.K. 5.15 closes the remaining hardware-lifecycle backlog tail — notification, dashboard
surfacing, scheduling — and builds the discovery-checkpoint layer the roadmap had assumed already
existed. Every requirement in this milestone extends an already-shipped subsystem; there is no
net-new capability territory.

- **Hardware Lifecycle Notifications (Phase 161, HWLC-14):** Opt-in email/webhook dispatch when a
  monitored device crosses a CNSA 2.0 tier boundary or an EOL/EOS date, delivered through the
  existing Phase 101 fan-out layer — no new delivery path, channel, or credential model. The
  trigger is a never-raising advisory hook on the drift-reconciliation success path, so a
  notification failure can never fail a scan. Deliveries land in the existing
  `integration_deliveries` audit table.
- **Vendor PQC Trend Surfacing (Phase 161, HWLC-19):** `GET /api/hardware/vendor-trends` shipped
  in v5.14 with no consumer. It now has one: a Vendor PQC Status Trends section on the
  `/hardware` dashboard tab, plus matching sections in the CLI technical markdown, HTML, and DOCX
  reports, with caption parity across all three enforced by test. Advisory-only — structurally
  isolated from scoring and guarded mechanically.
- **Check-in Scan Scheduling (Phase 162, HWLC-20):** `quirk schedule add --check-in` puts
  HWLC-13's lightweight re-probe on a recurring cadence. `--target` becomes optional for check-ins
  (stored as a `(known fleet)` sentinel) and remains mandatory for profile scans, in both the CLI
  and the API. The `/schedules` page marks check-in jobs with an advisory chip.
- **Discovery Batch Checkpoint Granularity (Phase 163, DISC-08):** An interrupted discovery scan
  resumed via `--resume-scan-id` now skips the 1024-host batches that already completed. A /16
  interrupted at batch 60 of 64 previously re-probed all ~65,000 hosts on resume; it now re-probes
  only the ~4,000 in the unfinished batches. No new table and no schema change — the existing
  `ScanCheckpoint` mechanism is reused with a structured `discovery:batch-N` stage string. Works
  without the `--cache` flag. See `docs/operators-guide.md` §13.

## Fixes

- **SCHED-02 — every default-profile schedule died at argparse.** The dispatcher fell back to
  `schedule.profile or "balanced"`, a *score* profile value that `run_scan --profile` rejects, so
  any CLI-created schedule without an explicit profile was recorded "failed" with no reason. Live
  for three months; it survived because the dispatched argv was reachable only through `Popen`.
  `build_scan_argv()` is now a pure function that can be asserted directly.
- **Resumed discovery scans under-reported their own coverage.** The per-batch cache stored only
  discovered ports, so a skipped batch lost the per-host "undetermined" advisory records from its
  liveness pre-pass. On a 4,094-host range, a 3-batches-cached resume reported 1,014 hosts scanned
  against 4,034 for an uninterrupted reference. Discovered endpoint counts were correct throughout,
  so the report did not look broken — it looked like a completed smaller engagement. Found by human
  UAT and fixed in-phase.

## Release integrity

**5.15.0 is the first version published since 5.12.0.** v5.13 and v5.14 were developed and merged
to `main` but never released: their tags were two-component (`v5.13`, `v5.14`) and did not match
`release.yml`'s then-`v*.*.*` trigger glob, so pushing them fired no workflow — no run, no failure,
no signal. `v5.9` had failed identically. The trigger is now `v[0-9]*`, so a malformed tag can no
longer silently no-op. `pyproject.toml` moves 5.12.0 → 5.15.0 and carries the accumulated v5.13
and v5.14 work.

## Upgrading

```bash
pip install --upgrade quirk-scanner
quirk --version   # QU.I.R.K. v5.15.0
```

No migration required. New database columns are additive and created on first `init_db()`.
