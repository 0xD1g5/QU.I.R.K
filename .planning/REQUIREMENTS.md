# Requirements: QU.I.R.K. — v5.27 Launch Readiness

**Defined:** 2026-10-02
**Core Value:** A consulting-grade cryptographic inventory whose findings a consultant can hand to a
client without qualification. That includes every public claim about the tool being true.

**Milestone goal:** Make QU.I.R.K. ready to show the public. It should carry its own identity on
every product surface, every user-facing doc claim should be verified against the code, and a tagged
release should contain all of it.

**Launch gate:** the operator posts QUIRK on social media only after this milestone closes (HORIZON
rationale log, 2026-09-30 and 2026-10-02 rows).

**Sequencing constraint:** BRAND -> DOC -> REL. Brand lands first because the doc review retakes the
README hero screenshot and checks the README claim by claim; branding afterwards would mean redoing
both. REL lands last because the tag must contain the reviewed docs and the new identity.

   it excludes.

## v5.27 Requirements

### Brand adoption (BRAND)

- [ ] **BRAND-01**: PR #46 (brand identity v1, `docs/brand/`) is refreshed against `main` and merged
      with every required job green, as `scripts/branch_ci_state.py` defines required.
      `python3 docs/brand/build_logo.py` regenerates the committed SVGs byte-identically.
- [ ] **BRAND-02**: A dashboard user sees the brand primary logo in the wide sidebar and the mark in
      the narrow sidebar, in both themes. Both are inline SVG following `currentColor` and keep the
      accessible name "QU.I.R.K.". The 216-219 contrast and keyboard ratchets stay green over the new
      chrome.
- [ ] **BRAND-03**: The browser tab shows the brand favicon (SVG, PNG and ICO). A scripted raster
      pipeline produces the PNG and ICO; the renderer is a dev-only dependency and never a runtime
      extra. A generator-drift freshness gate fails if the committed rasters stop matching their
      SVG source, and it is listed in CLAUDE.md's generator-drift table.
      Note (Phase 222 D-14): renderer (resvg-py, dev-only) + scripts/build_brand_rasters.py + tests/test_brand_assets_freshness.py scaffold landed in 222 for the report-logo PNG; favicon PNG/ICO outputs remain.
- [ ] **BRAND-04**: The README shows the brand logo correctly on GitHub light and dark themes via
      `<picture>` + `prefers-color-scheme`, and it renders on PyPI (absolute
      `raw.githubusercontent.com` URL).
- [ ] **BRAND-05**: Generated reports carry a small "Generated by" brand logo in the footer or
      colophon: HTML/PDF/DOCX on disk, and the dashboard `/print` export unless excluded with a
      recorded reason. The client/consultancy cover logo (`report.branding.logo_path`) is unchanged.
- [ ] **BRAND-06**: The `--ds-accent` teal is explicitly decided, kept or changed, in the phase
      discuss as an operator design call. The decision is recorded with measured contrast ratios
      for both themes. If changed, the ratchets stay green. Brand Signal `#7FE001` is not adopted as
      a UI token, and the app background is not re-themed.
- [ ] **BRAND-07**: Every artifact pinning the old electric-blue branding is re-worded in the same
      phase: the branding test, `UAT-7-31` pass criteria, its `uat-disposition-ledger.jsonl` row, and
      a regenerated `uat-coverage-gaps.md`. No test is skipped or deleted to get there, and no surface
      still shows the old blue-Q favicon.

### Pre-launch doc review (DOC)

- [ ] **DOC-03**: The set of user-facing docs is enumerated from the repository, with each `docs/`
      file and root doc classified as user-facing or internal and a reason given, rather than taken
      from a hand list. Every checkable claim in each user-facing doc (commands, flags, install paths,
      scanner/connector names, config keys, output paths, version strings, feature assertions) is
      extracted into a claim ledger.
- [ ] **DOC-04**: Every claim in the ledger is verified by a method independent of the doc: run the
      command, grep the flag in source, or hit the registry. Each one is marked TRUE, FIXED (doc
      corrected) or REMOVED (claim deleted). Live capabilities the docs omit (scanners, connectors,
      CLI commands) are added. No claim stays unverified.
- [ ] **DOC-05**: `docs/quirk-master-guide.md` is regenerated after the source-guide edits, and its
      freshness gate is green. Every edited doc with a vault counterpart is synced to
      `20_Dev-Work/QUIRK/Guides/` in vault `Digs`.
- [ ] **DOC-06**: The README hero screenshot is retaken against the branded dashboard from the
      canonical DB (`./quirk-output/quirk.db`), showing correct (non-mirrored) score gauges. The
      unreferenced `dashboard-hero-1/-2.png` are removed or referenced.

### Release cut (REL)

- [ ] **REL-05**: The version is bumped to 5.27.0 in `pyproject.toml` (editable reinstall so
      `tests/test_version.py` passes) and at every version-string site (README, `docs/UAT-SERIES.md`
      header and UAT-1-02). `CHANGELOG.md` gains a `## [5.27.0]` section that covers both v5.26 and
      v5.27 out of `[Unreleased]`.
- [ ] **REL-06**: Tag `v5.27.0` is pushed and `release.yml` publishes to PyPI and GitHub Releases,
      with the release body composed from the CHANGELOG section rather than boilerplate.
- [ ] **REL-07**: After publishing, a clean venv installed from PyPI reports `quirk --version` =
      5.27.0, and the PyPI project page renders the README logo. The launch gate is recorded as
      closed in HORIZON.md and STATE.md.
