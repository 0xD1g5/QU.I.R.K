# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through actual failure in the session being paused, not predicted.

- [ ] **CONSTRAINT: the consequence ceiling COMPRESSES, it does not CLAMP.** `min(score, ceiling)`
      is the obvious implementation, looks simpler, and is a **regression**. It destroys every
      gradient below the ceiling, so on exactly the estates that most need remediation the score
      goes INERT. Measured under a hard clamp on the 31-host estate: renewing every expired
      certificate moved it **+0**, eliminating all plaintext HTTP **+0**, and strict/balanced/lenient
      collapsed to one identical number — the product's remediation roadmap would have shown "+0
      points" against every recommendation it makes. **Structural mitigation:** before touching
      `_consequence_ceiling()` or its application site, re-run the lift-and-profile probe recorded in
      `d92e928b`'s commit message. If lift is 0 or the three profiles agree, you have reintroduced
      the clamp.

- [ ] **CONSTRAINT: an inert score makes "score must not rise" properties pass VACUOUSLY.** My
      candidate simulation reported 27/27 and was **wrong** — it ran under a clamp, and a score that
      cannot move trivially satisfies P1/P2b. Compression re-exposed P2b, which survives all six
      changes. **Structural mitigation:** any property asserting a score does *not* move must be read
      alongside proof that the score *can* move on the same fixture. A passing non-monotonicity
      assertion on a pinned score is not evidence.

**Do not proceed until both boxes are checked.**
