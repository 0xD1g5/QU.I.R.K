## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Verifying a suite-wide property with a per-file run | Three full-suite-only failures sat red since Waves 1-2 undetected, two of them predating this session. Both failure classes are ordering-dependent by construction — the macOS fork SIGSEGV needs an earlier test to have initialised Network.framework, the Playwright teardown needs an earlier test to have used Playwright — so a per-file run is *structurally incapable* of observing either. | blocking | Run `pytest -q -m ""` (the full suite) before claiming any phase is verified. Never substitute a per-file run. |
| Reading a recorded count instead of recomputing it | The local pytest baseline in project memory named two failing nodes; neither failed in any of four full-suite runs. That memory has now been wrong THREE times, in both directions, and warns of itself that it has. | blocking | Recompute every count at run time with your own command. A disagreement between your measurement and a recorded one IS the finding. |
| A claim outrunning its evidence | Every real problem found this session was a record asserting more than it proved: a disposition attributing a skip to the wrong cause; a comment claiming per-route discrimination that held on 2 of 7 routes; a guard regex whose captured region ran to EOF. None was caught by re-reading the reasoning that produced it. | blocking | For each assertion, name the state of the world that makes it FAIL. If you cannot, it is a finding. Re-derive with a *different method* and treat disagreement as the result. |
| Fixing a finding by weakening the claim | The cheap resolution to "this check is too broad" is to narrow what it looks at until it stops complaining. | advisory | Narrow the *scope*, never the *assertion*, and red-prove both directions afterward — the real failure must still fail. |
| Trusting a hand-written handoff over disk | I reported Phase 206 as "paused at 5 of 13" from the hub note and memory index. On disk it has 13 plans, 13 summaries, both close artifacts and a ticked box — complete since 2026-09-21. | advisory | Check the filesystem before reporting any phase's status. |
