def main(argv: list[str] | None = None) -> int:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer input → subprocess argv | `main()` invokes `git` via subprocess with repo-relative paths and diff output it then parses |
| `.githooks/pre-commit` → Python interpreter | The shell wrapper invokes `python3` with a repo-root-relative script path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-151-03 | Tampering | `_run_git()` subprocess invocation | mitigate | List-form argv only (`subprocess.run([...])`), never `shell=True` with interpolated strings — matches `release_tag_hygiene.py`'s existing `_run_gh_json()` pattern; no user-controlled string is ever concatenated into a shell command |
| T-151-04 | Repudiation | `git commit --no-verify` hook bypass | accept | Git's own designed escape hatch — cannot be prevented by a pre-commit hook by definition; documented explicitly in `CONTRIBUTING.md` (Task 3) so the boundary is known, not silently assumed universal (RESEARCH.md Pitfall 2/3) |
| T-151-05 | Tampering | `.githooks/pre-commit` shell script content | mitigate | Kept intentionally logic-free (`set -eu`, one `python3` invocation, `exit $?`) — no interpolation of untrusted input into the shell script itself, all real parsing happens in the tested Python layer |

</threat_model>
