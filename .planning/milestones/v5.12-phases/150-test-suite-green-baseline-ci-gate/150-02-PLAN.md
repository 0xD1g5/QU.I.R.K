<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repository contents | Workflow-defined code executes with the workflow's `GITHUB_TOKEN` |
| Third-party GitHub Actions → CI job | External action code runs inside the job |
| PyPI → CI runner | `pip install -e ".[all]"` resolves and executes third-party package code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-04 | Elevation of Privilege | `linux-full-suite` job token scope | mitigate | No job-level `permissions:` override is added; the job inherits the workflow-level `contents: read` (IN-01). Asserted by the YAML check (`'permissions' not in j`). |
| T-150-05 | Tampering | Third-party actions (`actions/checkout`, `actions/setup-python`) | mitigate | Reuse the exact existing full-length commit SHAs with version comments; no floating `@v4`-style tags, no version bumps in this phase. |
| T-150-06 | Tampering | Supply chain via `pip install -e ".[all]"` | mitigate | Installs only the already-declared, already-shipped `all` extras group from `pyproject.toml` — no new package is introduced by this plan, so no new legitimacy checkpoint applies. `identity`/`hw` remain excluded, preserving the documented cryptography-downgrade avoidance; `tests/test_install_all_excludes_impacket.py` and `test_install_all_excludes_pysnmp.py` run inside this very job and guard the boundary. |
| T-150-07 | Information Disclosure | Test output printed to a public CI log | mitigate | The suite is unit/offline; the job sets no secrets and the workflow declares none. `-q` limits output volume. No `pull_request_target` trigger is used, so forked-PR code never runs with repository secrets. |
| T-150-08 | Repudiation | A red suite silently ignored | mitigate | No `continue-on-error` on the job; a non-zero pytest exit fails the build and is asserted in Task 2's acceptance criteria. |
| T-150-SC | Tampering | npm/pip/cargo installs | mitigate | Only pre-existing pinned/declared dependencies are installed; no `[ASSUMED]`/`[SUS]` package is introduced, so no blocking human legitimacy checkpoint is required for this plan. |
</threat_model>
