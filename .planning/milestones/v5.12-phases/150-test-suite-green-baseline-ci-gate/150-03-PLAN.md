Prove the new CI gate actually bites (D-07, Success Criterion 3) with a live-fire test against real
GitHub Actions: push a branch carrying one deliberately failing test, open a PR, capture the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local repo → public `origin` remote | Pushed branches and PRs are publicly visible on a public repository |
| PR branch workflow → GitHub Actions runner | Workflow definition is taken from the PR HEAD, so branch content controls what CI executes |
| `gh` CLI credentials → remote repository state | Branch creation, PR creation/closure, and branch deletion are performed with the operator's token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-09 | Tampering | Deliberately failing test leaking onto `main` | mitigate | The test is committed only on `ci/smoke-check-150`; the PR is closed unmerged; Task 2 asserts `git ls-tree origin/main` and `git log origin/main` return nothing for the file, and Task 3 has a human re-confirm. Branch protection on `main` additionally prevents an unreviewed merge. |
| T-150-10 | Denial of Service | Orphaned branch / open PR left behind on a public repo | mitigate | `gh pr close --delete-branch` plus explicit `git ls-remote` and `git branch --list` emptiness assertions in Task 2 and Task 3. |
| T-150-11 | Information Disclosure | CI logs and the public PR exposing internal detail | accept | The smoke test contains only a standard-library `assert` and a Phase-150 identifying message; the suite is offline/unit and the workflow declares no secrets. `pull_request_target` is not used, so secrets are never exposed to branch-controlled code. |
| T-150-12 | Elevation of Privilege | Branch-controlled workflow modification running with elevated token | mitigate | The workflow-level `permissions: contents: read` (unchanged by this phase) applies to the PR run; no job-level override and no write-scoped step is added on the branch. |
| T-150-13 | Repudiation | Claiming the gate works without proof | mitigate | This entire plan exists to produce falsifiable proof — two run URLs plus a `--log-failed` excerpt, human-verified in Task 3. |
| T-150-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages; CI installs only the pre-existing declared `.[all]` extras via the Plan 02 job. |
</threat_model>
