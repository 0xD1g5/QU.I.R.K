        """Union of tags backed by a successful release.yml run OR an existing Release object.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scheduled workflow → GitHub API | The guard reads Actions run history and Release metadata with `GITHUB_TOKEN` |
| Repository tags → guard script | Tag names are attacker-influenceable strings (anyone with push access can create a tag) that flow into a `run:` step |
| Baseline file → guard verdict | A checked-in file can suppress a failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-148-07 | Elevation of Privilege | `release-tag-hygiene.yml` permissions | mitigate | Explicit workflow-level `permissions: {contents: read, actions: read}` with no write scope of any kind (WR-04) — a deliberate departure from the `python-staleness.yml` analog, which relies on repo defaults. Test-enforced: the static test asserts no `write` value appears in the permissions block. |
| T-148-08 | Tampering | Tag name injected into a shell/`run:` step | mitigate | Tag names are never interpolated into a shell command or into `${{ }}` expressions. The workflow's only `run:` line is the literal `python scripts/release_tag_hygiene.py`; tags are read inside Python via `subprocess` with a list argv (`["git", "tag", "--list"]`), never `shell=True`, and are only ever compared/printed. |
| T-148-09 | Repudiation | Guard silently passing when it cannot see the data | mitigate | `main()` treats a `gh` non-zero exit or unparseable JSON as a hard error (exit 2), never as "all tags backed". `fetch-depth: 0` on checkout prevents the shallow-clone variant of the same vacuous-green failure, and is test-asserted. |
| T-148-10 | Tampering | Baseline file used to mute a real, current failure | mitigate | Baseline entries require a written reason, live in a reviewed file under `.github/`, are enumerated in the job summary as `EXEMPT` (never hidden), and the runbook states the file must not be used to silence a current release failure. Seeded only with tags that already existed at implementation time. |
| T-148-11 | Information Disclosure | Job summary content | accept | The summary contains only tag names and release-run status — already public repository metadata. |
| T-148-SC | Tampering | Third-party Action supply chain | mitigate | Only `actions/checkout` and `actions/setup-python` are used, both at the exact 40-hex SHA pins already present in `python-staleness.yml` (WR-03); no new pin is introduced and a static test enforces SHA-pinning on every `uses:`. The script uses the standard library only — no `pip install` step exists in the workflow, so the package-legitimacy gate does not apply. |
