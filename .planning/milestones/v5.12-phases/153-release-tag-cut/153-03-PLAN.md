<objective>
OPERATIONAL CONSTRAINT: This plan's tag-push task MUST be executed via direct foreground
orchestration with explicit human confirmation immediately before `git tag`/`git push --tags`
runs. It must NEVER be dispatched to an autonomous background executor agent or run under
/gsd:autonomous's auto-chain, since GSD's checkpoint:decision auto-approves its first option in
auto-mode, which would silently bypass this requirement.

Isolate the single hard-to-reverse, externally-visible action in this phase — creating and
pushing the `v5.12.0` git tag — behind an explicit, blocking human-confirmation checkpoint, then
execute it once approved.

Purpose: per `153-CONTEXT.md`'s LOCKED decision, this step "requires an explicit pause for user
confirmation before it runs, regardless of what a PLAN.md task says or how confident an executor
is." Pushing an immutable tag turns any undiscovered pipeline bug into a permanent gap in release
history (the exact `v5.11.0` precedent this milestone exists to close) — this plan exists solely
to make that pause impossible to skip, per Pitfall 5 in `153-RESEARCH.md`: "nothing in a PLAN.md
task's literal text enforces a pause unless the task is explicitly marked as a checkpoint."

This plan's sole job is the tag/push. It performs no other work — Plans 153-01 and 153-02 already
proved the pipeline is green and the version bump is committed; Plan 153-04 verifies the tag push
after the fact.
Output: `v5.12.0` tag created and pushed to `origin`, only after explicit human approval.
</objective>
