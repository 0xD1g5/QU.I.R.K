_derive_all_profiles() {
  if command -v yq >/dev/null 2>&1; then
    yq eval '.. | select(has("profiles")) | .profiles[]' "${COMPOSE_FILE}" 2>/dev/null | sort -u

    grep -E '^[[:space:]]*profiles:[[:space:]]*\[' "${COMPOSE_FILE}" \

}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gateway container ↔ host Docker daemon | `cap_add: NET_ADMIN` grants the gateway container elevated network-namespace privileges beyond every other lab service's default (except `sensor.Dockerfile`'s `NET_RAW`) |
| Gateway container's FORWARD chain ↔ dead subnet | Any misconfigured/missing REJECT rule silently degrades to either silence (masking the intended behavior) or, in the worst case, unintended forwarding |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-152-01 | Elevation of Privilege | `segnet-gateway` (`cap_add: NET_ADMIN`) | mitigate | Capability scoped to only the gateway container, not the whole compose file; container never runs `--privileged`; this is a local dev/test-only chaos lab (never deployed, matches the lab's existing `sensor.Dockerfile` `NET_RAW` posture) — documented inline in the compose comment block per Task 1 |
| T-152-02 | Denial of Service (lab-scope only) | `segnet-gateway` FORWARD rules | mitigate | Task 1's 2-host smoke test runs BEFORE Task 2 scales to the full ~50-100-address representative range, exactly to catch a misconfigured REJECT rule (e.g. wrong chain, forwarding not enabled) before it silently produces false "unreachable" results across the whole range |
| T-152-SC | Tampering (supply chain) | N/A — no new pip/npm/cargo package installed this phase | accept | `iptables` is installed via `apk add` (Alpine base package manager) inside a local-build Dockerfile, not a QUIRK application dependency; Package Legitimacy Gate is not applicable per RESEARCH.md |
</threat_model>
