The discharge is the event that tested that clause — the prohibited clearing path was available and
was not taken.

## T-7 (new) — CLAUDE.md's generator-drift table is one row short

CLAUDE.md states "**Three** generator-drift gates" and tables `test_error_codes_freshness.py`,
`test_severity_bands_freshness.py`, `test_score_strings_freshness.py`. Enumerated from source:

```
grep -ln "byte-identical\|Regenerate with\|do not hand-edit" tests/*freshness*.py
```

returns **four** — the fourth being `tests/test_uat_coverage_gaps_freshness.py`, gating
`docs/uat-coverage-gaps.md`, regenerated with
`.venv/bin/python -m scripts.generate_uat_coverage_gaps > docs/uat-coverage-gaps.md`.

This matters operationally: CLAUDE.md's instruction for a red gate branches on *which kind* it is.
A session hitting `test_uat_coverage_gaps_freshness.py` red, and not finding it in the table, would
look for a `last_verified` field to bump — there isn't one — instead of regenerating. That is the
precise failure mode the table exists to prevent.

It is also **the sixth recorded instance of this project's signature defect**: a hand-maintained
list of sites drifting from the real set. CLAUDE.md's own Staleness section warns "Do not trust this
list — regenerate it" about the date-gated catalogs, and the GSD `state.*` section records four more.
The generator-drift table immediately below the warning was never held to it.
