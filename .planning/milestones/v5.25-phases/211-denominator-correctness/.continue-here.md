# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each was discovered through an ACTUAL FAILURE this session, not
> predicted. Acknowledge each explicitly before proceeding.

- [ ] CONSTRAINT: **Doc-before-evidence ordering** — a plan that WRITES ABOUT a measurement
      completed before the plan that TAKES the measurement, and published a FALSE claim to two
      client-facing guides. Structural mitigation: any plan whose content is a claim about another
      plan's evidence MUST declare an explicit `depends_on` that plan, even when their
      `files_modified` are disjoint. Wave co-membership is NOT ordering.
- [ ] CONSTRAINT: **A requirement is a claim about current behaviour, and claims expire** — Phase
      211's DENOM-01/02/03 were written 2026-09-27 describing a defect fixed on 2026-09-13. Four
      planning documents agreed with each other and all four were wrong. Structural mitigation:
      before accepting any requirement, verify the defect STILL REPRODUCES on `main` by reading code
      and running `git merge-base --is-ancestor <fix> HEAD`. Internal consistency across planning
      docs is evidence of nothing — they are copies of one another's assumptions.
- [ ] CONSTRAINT: **A cross-surface equality test goes vacuous once the surfaces are unified** —
      after Phase 210 put both pipelines on one shared function, `assert A == B` passed while the
      shared dedupe was sabotaged, because a bug moves both sides together. Structural mitigation:
      pair every equality assertion with PINNED ORACLES asserting absolute expected values, and
      prove the test red by breaking the code.

**Do not proceed until all boxes are checked.**
