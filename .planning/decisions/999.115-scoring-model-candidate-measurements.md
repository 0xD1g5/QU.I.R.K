# 999.115 — candidate scoring models, measured against the calibration ladder

**Status: EVIDENCE, not a locked decision.** The model choice is the operator's. This file records
what each of 999.115's candidate shapes actually does when run through the ladder, so that choice is
made from measurement rather than argument — which is the requirement 999.115 itself sets.

**Measured 2026-09-14** against `tests/test_score_properties.py`'s five rungs, on the code at commit
`e337bbd4`. Reproduce with the harness described under *Method*.

---

## Method, and why it is trustworthy

Every candidate was measured by **monkeypatching the real scorer's internals** —
`quirk.intelligence.scoring._ratio`, the `weights=` parameter the public API already accepts, and a
post-processing ceiling — never by reimplementing scoring in a prototype. A reimplementation would
have measured the prototype, not the product. That is the same "measure with a method independent of
the audited code" discipline that caught three false zeroes in the session that filed 999.115.

**Control:** the baseline run must reproduce the recorded ladder `[100, 95, 91, 85, 87]`. It does.

**Candidate B (start-at-zero / earn-points) was NOT measured, and its absence is itself a finding.**
B requires complement counters — "endpoints using TLS" as well as "endpoints plaintext", "certs
valid" as well as "certs expired" — which the evidence dict does not carry. 999.115's row argues B
is "far cheaper than it first appears because every ratio already computed has a complement", and
that is true *arithmetically*; but the complements are not *present*, so B cannot be evaluated
without first shipping evidence changes. Any simulation would have been invented data. **B is
therefore not a peer of A/C/D for this decision — it is a larger change that must be costed
separately.**

Columns below: `hits` = rungs landing in their operator-assigned band; `bands` = distinct bands
across the ladder; `spread` = max − min; `mono` = ladder monotonic; `sat` = subscores pinned at 0 or
25 out of 30 (saturation — the failure mode 999.115 warns candidate A produces).

## What the measurements say

**1. C — an absolute consequence term — is the load-bearing change.** Alone it moves the ladder from
1/5 to 3/5, makes it monotonic, and takes the spread from 15 points to 75. No other single candidate
comes close. This is not a new mechanism: `cap_band_for_severity()` already applies exactly this
reasoning to the *band*; C extends it to the *number*. That the existing code already contains the
idea, applied one layer up, is the strongest argument for it.

**2. A — larger weights — is the one to avoid as a primary lever.** It does spread the scale, but
saturation climbs with it (19 → 20 → 23 of 30 subscores pinned at 0 or 25), and A×3+C+D produces the
worst saturation of anything measured, 24/30. 999.115 predicted this ("punishes ordinary estates
alongside catastrophic ones and collides domains at 0") and the measurement confirms it. A saturated
subscore is an uninformative one — the estate stops being describable even though the headline moved.

**3. D — a non-linear curve — does not do what it was proposed to do, but is worth keeping for a
different reason.** D alone never fixes monotonicity at any exponent and never moves R2 out of
EXCELLENT. Its real contribution is **reducing saturation**: every D variant holds at 15/30, better
than baseline's 19/30 and far better than A's. So D's value is keeping subscores *informative*, not
spreading the headline. It is a refinement, not the fix.

**4. R2 can only be fixed by the PQC gate, and this is the sharpest result.** R2 is hygienically
spotless and quantum-blind. It has no prevalence for D to curve and no severity for C to cap, so it
sits at 93-95 under every combination of A, C and D. The only thing that moves it is the operator's
own 2026-09-14 decision — "no PQC, no 100" — implemented as a **ceiling** rather than a bonus.
Adding it takes C+D from 3/5 to 4/5.

That it must be a ceiling and not a bonus is not a preference: P7b measured the existing +8.0
`agility_pqc_hybrid_bonus` being absorbed whole by `_apply_weighted_impacts`' `_clamp(total, 0, 25)`.
A bigger bonus would be absorbed too. The ceiling shape is the one that survives the clamp.

**5. The R4/R5 inversion is fixed by P8 alone, independent of any model shape.** Giving the
multihost fixture honest key types (`RSA: 17` instead of all-zero) drops R5 from 87 to 81, below
R4's 85, and the inversion disappears with no model change at all. This confirms the caveat recorded
on `test_ladder_is_monotonic`: that specific inversion was substantially fixture-borne. **It does not
make P8 a non-issue** — the underlying defect (unreported key types scoring as best-case) is real and
independent of the fixture.

## Recommended shape — three tiers

**Tier 1 — local defects, worth fixing regardless of which model is chosen. Effort S each.**

- **P8.** Gate the RSA-only penalty on key types being *known*. Today `rsa_count > 0 and ecdsa_count
  == 0` means all-zero counts escape both the penalty and the bonus, so absent evidence scores as
  best-case. Treat unknown as unassessed, not as good news — the same distinction
  `_endpoints_assessed` already draws at domain granularity.
- **P7b.** Convert the PQC signal from a bonus to a ceiling, per (4) above.
- **P5c.** Filter drivers by the assessed predicate (separate todo already filed).

**Tier 2 — the model. `C + PQC gate`.** An absolute consequence ceiling plus the quantum-readiness
ceiling. Together these do essentially all the work: 4/5, monotonic, spread 75, saturation no worse
than today.

**Tier 3 — refinement. `+ D`.** Adopt the non-linear curve for its saturation benefit (15/30 vs
19/30), not for the headline. Exponent choice is insensitive across 0.4–0.6.

**Do not adopt A as the primary lever.** Consider it only as a late trim once C and the gate are in,
and watch saturation when doing so.

---

## The caveat that matters most

**5/5 is not the achievement it looks like.** The ladder has five rungs and C's ceiling table has
four free parameters. Fitting four parameters to five observations will hit every target whether or
not the shape is right — that is overfitting, not validation.

What is **robust** here is the ranking of *shapes*: C dominates, the PQC gate is the only thing that
touches R2, A trades spread for saturation, D buys saturation headroom rather than range. What is
**not robust** is the specific ceiling table (25 / 34 / 54 / 69). Those numbers should be treated as
a first fit and re-derived against more rungs before shipping.

Concretely, before Tier 2 lands: **add rungs**. The cheapest source is real scans — the 31-host
multihost estate is one real data point against four synthetic ones, and 999.115 is explicit that
this must be decided by measurement. A ladder of a dozen real estates would make the parameter fit
meaningful; five will not.

And the standing rule still governs all of it: **999.113 D5 — do not tune to a target.** Fitting to
operator-set calibration bands is the intended use of a ladder. Adjusting weights because a
particular number demos well is not, and the two are easy to confuse once a fitting harness exists.
