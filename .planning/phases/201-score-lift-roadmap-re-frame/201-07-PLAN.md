<objective>
Render score-lift on the HTML and DOCX deliverables, then machine-check that all four surfaces show the
SAME numbers for the same scan.

Purpose: LIFT-05 requires cross-surface consistency, and a consulting deliverable that contradicts the
dashboard destroys the number's credibility faster than having no number at all. The equality must be
asserted, not inferred from a shared content model.

Output: HTML template and DOCX renderer extensions, plus a four-surface numeric-equality test that also
carries LIFT-02's non-additivity assertion end to end.

Hard constraints:
- Renderers NEVER compute. Both surfaces read values already carried on `ExecContent` /
  `RoadmapItem` by plan 201-05. No `compute_item_lifts` import in either file.
- Copy is verbatim and identical to the CLI/dashboard surfaces: `(+N pts)`,
  `Projected score if all items resolved: {N}`, and
  `Advisory — this projection is a simulation and does not affect the readiness score.`
- HTML: mirror the existing `{% if item.effort is defined and item.effort %}` branch-guard shape so both
  the dataclass path and the raw-dict fallback path work. Keep the `| sanitize` filter on every
  scanner-derived string; the lift parenthetical is a server-computed number and must not be
  concatenated into a sanitized string.
- DOCX: use the defensive `getattr(exec_content, "projected_score", None)` /
  `getattr(item, "score_lift", None)` idiom the file already uses for additive fields.
- Absence renders nothing. No `(0 pts)`, no `(—)` on either surface.
- Do not touch `content_model.py`, `writer.py`, or `executive.py` (plan 201-05 owns them).
</objective>
