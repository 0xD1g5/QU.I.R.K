<objective>
Make the HTML/PDF report template overridable from `report.template_dir` and contain the trust
boundary that opens when it is — `SandboxedEnvironment` unconditionally at the single env
construction site, proven by a dedicated SSTI payload test.

Purpose: this is the phase's internal GO/NO-GO gate (ROADMAP criterion 2). If the sandbox cannot
contain the payload corpus without breaking the packaged template, the phase stops here and
surfaces it. RESEARCH already de-risked this empirically against the installed jinja2 3.1.6 — the
packaged template's `list.append` idiom works under a plain `SandboxedEnvironment` (only
`ImmutableSandboxedEnvironment` blocks mutation), so no template fix is expected.

Output: a sandboxed, override-capable HTML renderer; `tests/test_report_template_sandbox.py`; a
written gate verdict.

Hard constraints:
- ONE env construction site. Do NOT add a second "trusted" env path for the packaged template.
- `select_autoescape(["html", "j2"])` stays on the SAME instance; `env.filters["sanitize"]` must be
  re-registered on the sandboxed env or scanner-data XSS hardening silently regresses.
- The renderer must read `template_dir` with the double-getattr shape so a cfg with no `report`
  section (every existing fixture) behaves exactly as today. `ReportCfg` does not exist yet — it
  lands in plan 200-02, in parallel; do not import it and do not touch `quirk/config.py`.
- Do NOT assert anything against rendered PDFs (Playwright PDF legs are order-dependent-flaky —
  the skipped legs at `tests/test_report_injection_hardening.py:161/197/239`). HTML layer only.
</objective>

| scan data → override template output | Scanner-derived strings continue to flow into a template the operator may have rewritten. |

| T-200-02 | Tampering | Scan-data XSS regression if autoescape or the sanitize filter is dropped during the swap | mitigate | `select_autoescape(["html","j2"])` stays on the same instance; `env.filters["sanitize"]` re-registered; dedicated autoescape + sanitize-filter test legs |
