## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config.yaml → config loader | Path-shaped strings (`logo_path`, `template_dir`) enter the process and later drive filesystem reads and template resolution. |
| dashboard HTTP client → scan submission / effective-config view | The class of surface that must NEVER accept or echo a filesystem path, per the `assessment.logo_path` lesson. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-200-05 | Information disclosure | Path traversal via `report.template_dir` / `report.branding.logo_path` reaching arbitrary filesystem locations | mitigate | ONE named guard (`validate_report_path_field`) called at load time from `config_from_dict`, rejecting `..` parts with a coded `CONFIG-003` error naming field and value |
| T-200-06 | Elevation of Privilege | A future change exposing a report path field through a dashboard schema or overlay allowlist, giving a remote client filesystem reach | mitigate | Runtime-enumeration sweep over every `schemas.py` BaseModel, every `_KNOWN_*_OVERLAY_KEYS`, and `_SECTION_TITLES`; enumeration asserted non-vacuous and demonstrated able to fail |
| T-200-07 | Tampering | Unsafe YAML deserialization of operator config | accept | `load_config` already uses `yaml.safe_load` exclusively; this plan adds no new load path |
| T-200-08 | Denial of Service | A hard-failing guard breaking previously-working runs over a merely-missing logo file | mitigate | `logo_path` asymmetry: traversal rejected, missing file warns only; render-time `_load_logo_b64` tolerance preserved |
| T-200-SC | Tampering | npm/pip/cargo installs | accept | No packages installed by this plan |
</threat_model>
