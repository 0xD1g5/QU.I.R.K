<objective>
Render the full branding set on the two surfaces that can show it fully: HTML/PDF and DOCX.

Purpose: RPT-01's visible half. The config plumbing landed in 200-02 and the sandboxed loader in
200-01; this plan makes `report.branding.*` actually appear on the deliverable, with
`assessment.logo_path` still honored so no existing engagement config breaks.

Output: branded HTML template + renderer context, branded DOCX, and a presence-based cross-surface
test file.

Hard constraints:
- Read every new cfg value with the double-getattr shape
  (`getattr(getattr(cfg, "report", None), "branding", None)` then `getattr(..., field, None)`).
  Existing fixtures are `SimpleNamespace` cfgs with no `report` attribute and they must keep
  rendering exactly as today.
- ALL `docx.*` imports (including `docx.shared.Inches` and any header/footer enums) stay INSIDE
  `render_docx_report`'s body. A module-level docx import breaks minimal installs (T-100-DEP).
- Reuse `_load_logo_b64` (html_renderer.py:142) unchanged for logo loading — do not write a second
  image loader. Its size cap, mime detection, and never-raises contract are the graceful-degradation
  mechanism.
- Presence-not-appearance: assert that strings/fields are PRESENT in output. Visual fidelity
  (placement, sizing, cover layout) is a human-UAT concern, recorded as a manual verification in
  200-VALIDATION.md — do not write pixel/order assertions and do not assert against generated PDFs.
- PDF needs no work: it is a Playwright print of this same HTML.
</objective>
