  <action>
    Add a new numbered section `## 10. Discovery Liveness Pre-Pass` to `docs/operators-guide.md`,
    following the existing numbered-section style. Cover, concretely:
    - What it does: before each discovery batch's full `-sT` port sweep, QUIRK runs
      `nmap -sn -PS<port-list>` against that batch; hosts that do not answer are skipped from the
      sweep. This is TCP-based, not ICMP, so it works in segmented networks where ICMP is filtered.
    - Which ports it probes (D-03): the same port list the sweep itself uses. For the `top1000` and
      `all` port scopes the pre-pass uses the full `-PS-` 1-65535 range, because `-PS` has no
      `--top-ports` equivalent and a superset can never wrongly mark a host non-responsive.
    - Privilege fallback: nmap silently substitutes a TCP connect probe for the SYN probe when the
      process lacks raw-socket privileges, and its output is byte-identical either way. QUIRK
      therefore checks `os.geteuid()` once per scan and, when not running as root (or when the
      platform provides no way to check, e.g. Windows), logs a message AND records a
      `privilege_fallback` advisory row. Results remain valid; the pre-pass is just slower than
      intended. Running the scan as root (or with `sudo`) removes the advisory.
    - What happens on failure: if the pre-pass itself errors, QUIRK sweeps the entire batch
      unfiltered rather than losing hosts.
    - Where to look afterward: `liveness_skip` rows in the scan artifact identify each skipped host.
    Quote the exact advisory and skip-row strings as they appear in the shipped code (read them from
    `run_scan.py`, do not paraphrase).

    In `docs/report-interpretation.md`, document the two new `scan_error_category` values alongside
    the existing category explanations: `liveness_skip` (one row per host, `port=0`,
    `protocol="ADVISORY"`, `host` = the real host address — means the host did not answer the
