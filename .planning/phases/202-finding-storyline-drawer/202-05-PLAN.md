<objective>
Add the theme-framed score-lift attribution to the storyline endpoint — D-01's load-bearing data, and
per D-07 the drawer's most reliable value.

Purpose: every piece of this already exists in the codebase as a tested, named function. The entire
implementation risk is in the JOIN ORDER between them — dashboard title -> CLI canonical title ->
fingerprint -> `(scan_run_id, fingerprint)` rows -> slug -> `item_progress` / `compute_item_lifts` —
and in the three verified facts that break the naive version: `FindingItem.id` is not unique, the two
title vocabularies diverge, and 41% of real fingerprints belong to two themes at once.

Output: the theme-attribution half of `storyline.py`, a shared lift-context helper extracted from
`scan.py`, and the second half of the backend test file.

Hard constraints:
- **Dividing `theme_score_lift` by any count is a BLOCKER** (D-01, UI-SPEC Invariant 3). Lifts are
  not linear in constituent count, so manufactured shares would not sum back to the theme lift; and
  it fabricates a number the scorer never computed. This applies to the server side as hard as to the
  client side — a reviewer finding one treats it as a blocker.
- **Do NOT fix `int(delta)`** (`quirk/intelligence/score_lift.py:164`). It is a tracked follow-up at
  `.planning/phases/201-score-lift-roadmap-re-frame/deferred-items.md` item 4 and it moves an
  operator-approved displayed number on four surfaces. Out of scope, explicitly deferred.
- **Do NOT change how score-lift is COMPUTED.** Phase 201 owns that. This plan only reads it through
  the existing call.
- **Do NOT introduce a hand-ordered `_SLUG_PRIORITY`-style preference list as the tie-break.**
  `202-RESEARCH.md` recommends exactly that and D-08 **explicitly REJECTED it** (CONTEXT outranks
  RESEARCH on conflict). The rule is one sentence: prefer the specific title-based theme, never the
  severity catch-all. `_SLUG_PRIORITY` may be *read* if you need a deterministic order among two
  specific themes, but the catch-all exclusion must not be expressed as its rank.
- **Zero writes.** No `session.add`, no `session.commit`, no fingerprint row creation. The CLI
  pipeline owns `RemediationItemFingerprint`; the dashboard only reads it.
- Never `str(exc)` in an HTTP detail; never reflect the `title` query param.
- `.venv/bin/python`, never bare `python`.
- Plain `git add` + `git commit`; never the gsd `commit --files` wrapper. Do NOT invoke any mutating
  GSD verb, and do not touch `.planning/STATE.md`.
- If any new test calls `write_reports`, it MUST patch `quirk.reports.writer.render_pdf_report` at the
  writer seam (TRIAGE-149). This plan should not need it.
</objective>
