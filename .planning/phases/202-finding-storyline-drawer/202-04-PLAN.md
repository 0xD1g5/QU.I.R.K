<objective>
Build the drawer's two content sections and their eight states as one self-contained, fully-tested
component, so plan 202-06 only has to mount it.

Purpose: D-01's honest theme framing is this phase's hardest design problem and the UI-SPEC specifies
it structurally rather than in prose precisely so it is checkable. The number this drawer renders is
the one value an operator will mis-attribute: one theme's `+4 pts` is shared across N findings, and
rendering it as a per-finding number would tell the operator that resolving THIS finding yields 4
points when 4 points requires resolving the theme. Isolating all of that in one component with its
own test file is what makes Invariants 1-3 assertable.

And per D-07, **absence is the common path**. Most findings carry no algorithm keyword, so A5 is what
operators will see most often. It is built here as a first-class state with real copy — not a
fallback branch — and the attribution block, which is the drawer's reliable value, stays fully
populated when it fires (S6).

Output: `FindingStorylineSections.tsx` exporting `StorylineSections`, plus its vitest file.

Hard constraints:
- **Division of `theme_score_lift` by any count is a BLOCKER** (D-01, UI-SPEC Invariant 3) — in any
  form: intermediate variable, inlined expression, comment-documented "approximate share", tooltip,
  or `title` attribute. A reviewer finding one treats it as a blocker, not a nit. The mechanical
  trip-wire in Task 2 is mandatory, not optional.
- **Every string is exact and greppable.** Do not paraphrase, re-case, or re-punctuate the copy in
  `<interfaces>`. A reviewer must be able to `grep -F` each one. Use the single character `…`
  (U+2026), not three ASCII periods.
- **Spacing: strict multiples of 4.** No `.5` Tailwind step (`gap-1.5`, `-mt-0.5`, `mt-1.5`,
  `space-y-2.5`, `p-1.5`), no bracket spacing (`mt-[6px]`), no inline `style` spacing. `roadmap.tsx`'s
  existing off-grid occurrences are explicitly NOT precedent and must not be copied. Where a tight
  inline gap is needed, use `gap-1` (4px).
- **No hardcoded hex, rgb, or `hsl(...)` literal.** All colour via `--ds-*` custom properties or
  shadcn `hsl(var(--token))` utilities. `findings.tsx`'s `SEVERITY_STYLES` and its inline
  `quantum_risk` colour map use bracket `hsl(...)` literals — pre-existing, out of scope, and must
  not be extended or copied.
- **Accent (`var(--ds-ok)`) is reserved for exactly one element**: the `+N` glyph. Not the theme
  title, not the condition clause, not the position or closure sentences, not the disclaimer, not
  the narrative.
- **`null` checks use `!= null`, never truthiness** — `if (theme_score_lift)` treats a legitimate `0`
  as absence.
- `.tsx` edits require `npm run lint && npm run test` from `src/dashboard/`. This plan adds a
  component that nothing mounts yet, so **no `npm run build` and no statics commit** — 202-06 owns
  the rebuilt `quirk/dashboard/static/`. A stray static diff here makes that plan's diff unreadable.
- Plain `git add` + `git commit`; never the gsd `commit --files` wrapper. Do NOT invoke any mutating
  GSD verb, and do not touch `.planning/STATE.md`.
