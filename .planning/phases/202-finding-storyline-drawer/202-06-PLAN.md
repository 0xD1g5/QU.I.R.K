<objective>
Wire the storyline into the findings page: a keyboard-operable per-row trigger, the extended Sheet,
the full focus contract, and the two pre-existing Sheet defects the UI-SPEC requires this phase to
correct as a side effect.

Purpose: success criterion 1 is that the operator never leaves the findings view, and success
criterion 4 is a real focus contract. Today neither is achievable — the drawer opens from an
`onClick` on a `<TableRow>`, which is not focusable and not keyboard-operable, so the drawer is
unreachable by keyboard at all. Criterion 4's a11y capture (plan 202-07) asserts against this plan's
output, so the focus behaviour has to be right here before the baseline is taken.

Output: the extended `findings.tsx`, a vitest file for the integration behaviours, and the rebuilt
statics.

- **`.tsx` edits REQUIRE `npm run build && npm run lint && npm run test` from `src/dashboard/`, and
  the rebuilt statics under `quirk/dashboard/static/` MUST be committed with the source.** FastAPI
  serves pre-built statics; a phase-201 plan shipping un-rebuilt statics produced a false "no badge
  appears" defect report, and Phase 195 hit the same thing. This plan is the one that owns the
  statics commit for the phase.

  `style` spacing. The pre-existing off-grid occurrences in `roadmap.tsx` (`gap-1.5` at :256/:295,
  `-mt-0.5` at :286, `mt-1.5` at :340) are explicitly NOT precedent and must not be copied into
  `findings.tsx`. `480px` is the ONE pixel literal this phase may introduce, as a utility-class
  breakpoint value, and it is a multiple of 4.
- **No new hardcoded colour.** `findings.tsx`'s existing `SEVERITY_STYLES` (:25-31) and its inline
  `quantum_risk` colour map (:89-93) use bracket `hsl(...)` literals — pre-existing, unchanged, out
  of scope, and **must not be extended or copied** by the new column or the new sections.
- **Do NOT add a drawer library** (D-03). No `vaul`. "Drawer" means the existing
  `src/dashboard/src/components/ui/sheet.tsx`.
- **Do NOT add a `tests/console-allowlist.json` entry** for the Radix description warning. Render the
  `SheetDescription` — that is the correct fix and the a11y win the warning exists to prompt.
- The findings table's existing columns, filters, pagination, severity badge colours, and the
  page-level skeleton/empty states are unchanged and out of scope. The new column is the rightmost.
- `null` checks use `!= null`, never truthiness.
- Plain `git add` + `git commit`; never the gsd `commit --files` wrapper. Do NOT invoke any mutating
  GSD verb, and do not touch `.planning/STATE.md`.
