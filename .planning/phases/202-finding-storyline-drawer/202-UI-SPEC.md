# Phase 202 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Scope discipline (per 202-CONTEXT.md D-01..D-05 and the ROADMAP's 4 success criteria):** this is
> an EXTENSION of the **already-existing** finding-detail `Sheet` in
> `src/dashboard/src/pages/findings.tsx` (lines 218-254) — not a new drawer, not a redesign of the
> findings table. This spec locks new surface area only: the per-row storyline trigger, the
> narrative section, the theme-framed score-lift attribution block, the drawer's loading / error /
> honest-absence states, the focus-and-keyboard contract, and their copywriting. The findings
> table's existing columns, filters, pagination, severity badge colors, and the page-level
> skeleton/empty states are unchanged and out of scope.

> **Pre-existing surface this phase must correct as a side effect (both are gate-relevant, not
> cosmetic):** the Sheet today sets width via inline `style={{ width: 480 }}`, which overrides
> `sheetVariants`' responsive `w-3/4 sm:max-w-sm` and overflows viewports narrower than 480px
> (see Responsive Contract); and the Sheet renders no `SheetDescription`, which surfaces a Radix
> dev console warning the moment the a11y harness opens it (see Focus & Keyboard Contract, F8).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` / `var(--ds-bg-page)` | Page background; `SheetContent`'s own `bg-background` (already set by `sheetVariants`) |
| Secondary (30%) | `hsl(var(--card))` / `var(--ds-bg-surface)` with `hsl(var(--border))` | The attribution sub-panel shell (`rounded-lg border border-border bg-card p-4`); the drawer overlay scrim is the primitive's existing `bg-black/80` |
| Accent (10%) | `var(--ds-ok)` (`#3fa876` dark / `#2c8a5d` light) | **Reserved exclusively for ONE element: the theme score-lift `+N` glyph inside the attribution block's lift sentence.** Nothing else new in this phase uses it |
| Destructive | `hsl(var(--destructive))` | **Not used.** The drawer is read-only — no destructive action exists in this phase |

**Accent reserved for:** the single `+N` numeral in the attribution block's lift sentence, rendered
at Display (20px/600) in `var(--ds-ok)`. That is the complete list. Specifically NOT accented: the
theme title, the `pts when …` condition clause, the position sentence, the closure sentence, the
narrative text, the row trigger button, any badge, any section label.

Rationale (ties to D-01): the lift number is the one value in this drawer an operator will
mis-attribute. Making it the *only* accented glyph means the eye that lands on it lands inside the
sentence that qualifies it, and there is no second accented number anywhere to invite comparison,
subtraction, or summation.

**Error/absence tone:** honest-absence and error copy render in `text-muted-foreground`
(`var(--ds-text-muted)`) — never `--ds-critical`, never `--ds-high`. An absent value is not a
failure state and must not be tinted as one. A failed *fetch* is also muted, not
destructive-tinted: the project's convention is a calm honest statement plus a recovery path, and
an alarm color would imply the finding itself is worse than it is.

**No hardcoded hex, rgb, or `hsl(...)` literals** in this phase's new code. All color goes through
`--ds-*` custom properties or shadcn `hsl(var(--token))` utility classes. The pre-existing
`SEVERITY_STYLES` map (`findings.tsx:25-31`) and the inline `quantum_risk` color map
(`findings.tsx:89-93`) both use hardcoded bracket `hsl(...)` values — they are pre-existing,
unchanged, out of scope, and **must not be extended or copied** by this phase.

**Canvas hazard:** not applicable — this drawer renders no canvas. No `var(--…)` string is passed
to Cytoscape, Recharts, or any 2D context (the Phase 195 failure mode cannot recur here because no
new chart or canvas component is introduced; a chart in this drawer is explicitly out of scope).

## Copywriting Contract

All strings below are **exact and greppable**. An implementer must not paraphrase, re-case, or
re-punctuate them; a reviewer should be able to `grep -F` each one.

| Element | Copy |
|---------|------|
| Primary CTA (per-row trigger) | `Storyline` — button label in the new rightmost table column, whose header is also `Storyline`. Accessible name: `aria-label={`Open storyline for ${title} at ${host}:${port}`}` |
| Drawer narrative section label | `STORYLINE` (Label role, uppercase via the existing `uppercase` class on sentence-case source text `Storyline` — match `findings.tsx:234`'s pattern exactly) |
| Attribution section label | `SCORE-LIFT ATTRIBUTION` |
| Attribution theme line | `Remediation theme: {theme_title}` |
| Attribution lift sentence | `+{formatScoreNumber(theme_score_lift)} pts when all {theme_finding_count} findings in this theme are resolved` — the `+{N}` portion is the accented Display glyph; the rest of the sentence is Body/muted and **must be in the same paragraph flow as the number** (see Attribution Block Contract) |
| Attribution **position** sentence (independent — see below) | `This finding is {finding_position} of {theme_finding_count} in the theme.` |
| Attribution **closure** sentence (independent — see below) | `{theme_closed_count} of {theme_finding_count} findings in this theme are verified closed.` |
| Attribution disclaimer (**MANDATORY whenever a lift number renders**) | `This is the theme's total lift, not this finding's individual contribution. Resolving this finding alone does not yield the full amount.` |
| **A1** — finding is not mapped to a theme (`slug_for_title()` returned `None`) | `Not mapped to a remediation theme — no score-lift attribution exists for this finding.` No number, no theme line, no position sentence, no closure sentence, no disclaimer |
| **A2** — theme known but `theme_score_lift` is `null` | Theme line renders. Then: `Score lift could not be modelled for this theme in this scan.` No number, no disclaimer. Position and closure sentences still render **if their counts are available** — the lift being unmodellable says nothing about the constituent counts |
| **A3** — constituent counts unavailable (`theme_finding_count` is `null` or `0`) | Theme line renders. Then: `The theme's constituent findings could not be counted in this scan, so the lift cannot be stated with its condition.` No number, no disclaimer, no position sentence, no closure sentence. **Do not reuse A2's string here** — in this branch the lift *was* modelled; only the count is missing, and conflating the two misstates what happened. Never render `1 of 0`, `1 of null`, or `0 of 0`. **Precedence (UI-202-02):** A3 is checked before A2 — when `theme_finding_count` and `theme_score_lift` are *both* `null` simultaneously, the A3 string alone renders (never A2). Counts are logically prior to stating the lift's condition, so this is the contractual precedence, not an accident of implementation order |
| **A4** — `finding_position` alone unavailable (theme, lift, and counts all known) | Omit **only** the position sentence. The lift sentence, the closure sentence, and the disclaimer all render normally. No replacement copy: position is a *locator*, not a value, and its absence changes nothing about what the lift number means or how the reader should bound it — the closure sentence still conveys the theme's scale. This is the one absence in this spec rendered by silent omission rather than a sentence, and that is deliberate |
| **A5** — no catalog narrative for this finding (D-05) | `No catalog narrative exists for this finding type yet — the Description and Remediation fields above are the available guidance.` |
| **A6** — finding has no stable id (`FindingItem.id` is `null`) | The row's `Storyline` trigger renders **disabled** with `aria-label={`Storyline unavailable for ${title} at ${host}:${port}`}` and `title="Storyline unavailable — this finding has no stable identifier in this scan."`. The drawer is never opened in a state where it cannot fetch |
| Loading state | `Loading storyline…` as `sr-only` text inside a `role="status"` wrapper, alongside the visual skeleton (see Loading & Error Contract). Use the single U+2026 character `…`, not three ASCII periods — `findings.skeleton.tsx:6`'s `Loading...` is pre-existing and is not the precedent for new copy |
| Error state (fetch failed, any cause) | `Could not load the storyline for this finding.` followed by a button labelled exactly `Retry storyline` (`Button variant="outline" size="sm"`). One fixed string for all failure causes — never `str(exc)`, never a status code, never a URL, per the fixed-detail precedent in 202-CONTEXT's Established Patterns |
| Empty state (page level) | N/A — unchanged. Reuses `findings.tsx:119`'s existing `EmptyStateCard` message verbatim. With zero findings there are no rows, so no trigger and no drawer |
| Destructive confirmation | None — no destructive action in this phase's scope |

**Why position and closure are two sentences, not one** (this is a correctness requirement, not
formatting): `item_progress()` returns `(closed_count, total_count)` **unconditionally** from a row
query — it has no notion of this finding's position within the theme. So closure data is available
in strictly more situations than position data is. A single combined line makes the closure fact
hostage to the position fact, and A4 would then destroy a fact D-01 names explicitly (citing that
function's own `"6 of 8 verified closed"` docstring). Two sentences, independently suppressible,
with `theme_closed_count`/`theme_finding_count` gating only the closure sentence and
`finding_position` gating only the position sentence.

**Forbidden copy** (each would re-introduce the defect D-01 rejects, or a fabricated value):

- Any phrasing that attributes the number to the finding: `This finding is worth +4 pts`, `Score lift: +4 pts`, `Your score improves by 4 points`, `+4 pts available here`.
- Any per-finding share, however worded: `≈ +0.5 pts`, `your share: +0.5 pts`, `+4 pts / 8 findings`.
- `N/A`, `Unknown`, `—`, `0`, `0 pts`, `+0 pts`, or `null` as the rendered value of an absent lift. `—` is a value-styled glyph in this codebase (`findings.tsx:88` uses it for an absent `quantum_risk` *cell*, where a table cell must occupy space); the drawer is a prose surface with no column to hold open, so absence is a **sentence**, not a dash.
- A bare number with the condition in a separate element, tooltip, footnote, or `title` attribute.

## Attribution Block Contract (D-01 — the load-bearing section)

(Non-template section. D-01's honest theme framing is this phase's hardest design problem; it is
specified structurally here so it is checkable, not left to prose.)

**Placement.** A bordered sub-panel (`rounded-lg border border-border bg-card p-4 space-y-2`) in the
drawer body, rendered **last** — after Description, Remediation, and Quantum Context — and
**separated from the drawer's own severity/host badge row by at least md (16px)**. It must NOT be a
badge in the header badge row (`findings.tsx:226-231`). Reason: a chip sitting beside the severity
badge and the `host:port` string reads as a property *of this finding*, which is exactly the
mis-attribution D-01 forbids. Enclosing the number in its own titled, bordered region whose first
line names a *theme* is the visual mechanism that makes the scope of the number unambiguous.

**Required vertical order (top to bottom), no reordering:**

1. Section label: `SCORE-LIFT ATTRIBUTION` (Label, 12/600, `text-muted-foreground uppercase`, `mb-1`).
2. Theme line: `Remediation theme: {theme_title}` (Body 14/400; theme title `font-semibold`, the `Remediation theme:` prefix `text-muted-foreground`).
3. Lift sentence: one `<p>` containing `+{N}` as a `<span>` at Display/accent, immediately followed — **inside the same paragraph** — by ` pts when all {theme_finding_count} findings in this theme are resolved` at Body/`text-muted-foreground`.
4. Position sentence (Body 14/400, `text-muted-foreground`) — independently suppressible per A4.
5. Closure sentence (Body 14/400, `text-muted-foreground`) — independently suppressible per A2/A3.
6. Disclaimer: `Info` icon (`h-3 w-3`, `text-muted-foreground`, `aria-hidden="true"`) + the mandatory disclaimer string, in a `flex items-start gap-1` row at 12px/400 `text-muted-foreground`.

**Invariant 1 — single-node condition (restated to be literally testable).** The single `<p>`
element whose `textContent` matches `/\+\d/` must also match `/when all/`; and the accented `<span>`
holding `+{N}` must have **no block-level element between itself and that `<p>`** (i.e. the `<p>` is
the span's nearest block-level ancestor). Stated this way both halves are assertable and neither is
vacuous: the first clause pins number and condition into one paragraph's text flow, the second
forbids smuggling a `<div>`/`<br>`/grid cell in between that would visually separate them while
still satisfying a naive `textContent` check on an outer container.

This invariant is the one that survives every downstream change — responsive reflow, copy-paste into
a ticket, a screen reader reading the paragraph as a unit, or a future card-layout refactor — and it
is why the number is not allowed to be a standalone stat.

**Invariant 2 — disclaimer co-presence, over the enumerated states.** Across the eight states
enumerated in the State Matrix below (and no claim is made beyond them — this is a finite,
exhaustive check over this spec's own state list, not a universal quantification over all possible
DOM): in every state where the attribution panel renders a lift number, the disclaimer string
renders; in every state where it does not, the disclaimer does not. That yields **eight assertions**,
one per state, which a planner should write as a parametrised test rather than a single hand-wave.

**Invariant 3 — division trip-wire (mechanical, not a review rule).** Division of
`theme_score_lift` by any count must not appear in the source in any form — intermediate variable,
inlined expression, comment-documented "approximate share", or tooltip. Per D-01 a reviewer finding
one treats it as a **blocker**. Because grep cannot catch every spelling of a manufactured share,
this is additionally enforced by a rendering assertion: render the panel with
`theme_score_lift: 7, theme_finding_count: 2`, and assert the strings `3.5` and `3` appear **nowhere**
in the attribution panel's `textContent`. Those are the only two values a per-finding share could
round to for that input, so the test catches a fabricated share regardless of how it was computed.
(`7` and `2` must of course both appear — as the lift and the count.)

**Forbidden visuals in this block** (each fabricates or implies a per-finding number):

- A progress bar, segmented bar, donut, or any geometry whose segments map to constituent findings — it visually asserts that each finding is 1/N of the lift.
- A gauge, arrow, delta sparkline, or before/after pair.
- A table of constituent findings with a per-row points column.
- The position fraction (`1 of 8`) styled at Display size or in accent color — it is a *count*, and making it numerically prominent invites reading `1/8 × 4 pts`.
- `theme_score_lift` rendered anywhere else in the drawer (header, badge row, title) — exactly one occurrence per drawer.

## Number Formatting Contract

**Rule:** every score/lift numeric the drawer renders goes through `formatScoreNumber()` imported
from `@/lib/utils` — whole numbers render with zero decimals (`4`), fractional values with exactly
one decimal (`4.2`). The implementer **must not** re-derive this: no `.toFixed(…)`, no `Math.round`,
no `Number.prototype.toLocaleString`, no `String(n)`, and no raw template interpolation
(`+{theme_score_lift} pts`) at any call site.

This is not a style preference. Phase 201 shipped raw interpolation on this exact numeric family
(201-UI-C2/E1), which was invisible only because the backend happened to emit pre-rounded integers
(`quirk/intelligence/score_lift.py:164` does `int(delta)`); the remediation was to centralise
formatting in `formatScoreNumber()` so `roadmap.tsx` and `print.tsx` could not diverge. A third
surface re-deriving the rule re-opens that divergence.

**Applies to:** `theme_score_lift` (the only score-family numeric in this drawer).

**Does NOT apply to:** `finding_position`, `theme_finding_count`, `theme_closed_count`. These are
integer cardinal counts by construction (`item_progress()` returns `len(rows)` and a `sum(...)` of
booleans) and render raw. Do not wrap counts in `formatScoreNumber()` — doing so would imply they
can be fractional, which they cannot.

**Required regression coverage:** a test that feeds a fractional `theme_score_lift` (e.g. `4.27`)
through the drawer and asserts the rendered string is exactly `+4.3 pts when all 8 findings in this
theme are resolved` — the branch 201 left untested in both directions (201-UI-E5).

## Loading & Error Contract

The fetch is lazy (D-02): the drawer opens before data arrives. **The drawer must never be blank and
must never show a fabricated value while loading.**

**Immediately on open (zero-latency, from the row data already in hand):** the `SheetTitle`
(finding title), the severity badge, the `host:port` line, and the existing `description` /
`remediation` / `quantum_risk` sections all render from `FindingItem` with no skeleton — they are
already loaded. Only the narrative and attribution sections are pending.

**Loading treatment:** a `role="status"` wrapper containing `<span className="sr-only">Loading
storyline…</span>` plus visual `Skeleton` bars (reuse `@/components/ui/skeleton`, matching
`findings.skeleton.tsx`'s idiom):

- Narrative section: 3 bars — `h-4 w-full`, `h-4 w-full`, `h-4 w-3/4` (`h-4` = 16px matches Body's 14px/1.5 ≈ 21px line box closely enough and is the existing `Skeleton` row-height family; `space-y-2` between bars).
- Attribution section: the bordered sub-panel shell renders with its real `SCORE-LIFT ATTRIBUTION` label, containing one `h-4 w-40` bar and one `h-4 w-full` bar.

Rendering the real section labels over skeleton bars (rather than skeletonising the labels too)
keeps the drawer's structure stable across the load, so nothing reflows when data lands — and the
skeleton can never be mistaken for a rendered zero.

**Error treatment (S8):** on fetch failure, replace both pending sections with the fixed error
string plus a `Retry storyline` button. Requirements:

- `role="status"` on the error container (it is an informational state, not a page-level alert — `role="alert"` would interrupt a screen reader mid-drawer and over-escalates a non-destructive read failure).
- Muted text, not destructive tint (see Color).
- `Retry storyline` re-issues the same `GET /api/findings/{id}/storyline` without closing the drawer and without losing focus position; focus stays on the button while it is re-fetching (`disabled` + `aria-busy="true"` during the in-flight retry so it cannot be double-clicked).
- **Never** a silent empty panel, and **never** an error that falls through to any honest-absence string — a failed fetch and a genuinely absent catalog entry are different facts and must read differently. (Deliberate divergence from 201's posture, where a null was correctly indistinguishable from a computation failure because the firewall required it; here the client *knows* the request failed, so collapsing the two would discard information the client actually has.) The same rule is why A2 and A3 have distinct strings.
- No retry count, no backoff text, no stack trace, no URL, no HTTP status in the user-visible string.

**Close-while-loading:** closing the drawer mid-fetch must not leave a pending state write against
an unmounted component, and re-opening the same row re-issues the fetch rather than showing a
stale prior finding's narrative. Observable contract: the drawer never displays narrative belonging
to a different finding than the one named in its own `SheetTitle`.

## Focus & Keyboard Contract

D-04's a11y capture asserts these; each is named so it is individually testable.

**F1 — Trigger.** A new rightmost table column with header `Storyline`, whose cell contains
`<Button variant="ghost" size="sm">` with the **visible text label** `Storyline`,
`aria-haspopup="dialog"`, and `aria-label={`Open storyline for ${title} at ${host}:${port}`}`. A
leading lucide glyph is optional decoration only (`aria-hidden="true"`) — this is **not** an
icon-only button. Required because the current open affordance is `onClick` on a `<TableRow>`
(`findings.tsx:190-193`) — a non-focusable, non-keyboard-operable element, so today the drawer is
unreachable by keyboard at all.

**F2 — Row click preserved.** The existing row `onClick` stays as a redundant pointer affordance.
Because the Sheet is state-controlled (no `SheetTrigger`), Radix's FocusScope restores focus to
whatever was focused before open — which for a mouse click on the row is `<body>`, not the row. So a
row-click open must programmatically focus that row's `Storyline` button before setting open state
(or capture its ref and restore explicitly in `onCloseAutoFocus`). Either implementation is
acceptable; F6's assertion is what must hold.

**F3 — Focus placement on open.** Focus moves inside the `SheetContent`. Initial focus lands on the
Sheet's built-in Close (X) button (`sheet.tsx:65`, the first tabbable descendant) — the accepted
default; do **not** add `autoFocus` to a narrative paragraph or to the `Retry storyline` button.
Assertion: after open, `document.activeElement` is inside the `SheetContent` and has accessible name
`Close`.

**F4 — Focus trap.** Tab and Shift+Tab cycle only within the `SheetContent`; no focus reaches the
findings table, filters, or pagination while the drawer is open. Assertion: from the last tabbable
element in the drawer, Tab returns to the first tabbable element in the drawer.

**F5 — Esc closes.** Escape closes the drawer. Assertion: after `Escape`, the `SheetContent` is
removed from the DOM (Radix unmounts on close) and F6 holds.

**F6 — Focus returns to the triggering row.** On close by **any** means — Escape, the Close button,
or an overlay click — focus returns to the exact `Storyline` button of the row that opened the
drawer. Assertion: `document.activeElement.getAttribute('aria-label')` equals `Open storyline for
{that row's title} at {host}:{port}`. Must hold for a keyboard-initiated open and a mouse-initiated
open (F2), and for all three close paths.

**F7 — Overlay click closes** (Radix default, not to be disabled), with F6 holding.

**F8 — Accessible name and description are both wired.** `SheetContent` must render a
`SheetDescription` (already exported from `sheet.tsx:115`, currently unused by `findings.tsx`).
Content: the finding's `host:port` and protocol as the drawer's accessible description. Two concrete
reasons:

1. `@radix-ui/react-dialog` ^1.1.15 emits a dev console warning when a `Dialog.Content` has no description. The a11y harness (`run-a11y.mjs`) fails on **any** console output not matched by `tests/console-allowlist.json`, which today contains exactly one entry (a recharts `defaultProps` warning). Opening the drawer during the capture would therefore fail the gate on a console message. **Do not add an allowlist entry to suppress it** — render the description, which is the correct fix and the a11y win the warning exists to prompt.
2. The severity/host line already exists in the drawer body; wiring it (or an equivalent) as the dialog description costs no new visual surface.

**F9 — No new focusable element outside the trap.** The attribution block and narrative are static
text; no new tooltip-only, hover-only, or `title`-attribute-only information is introduced (a
hover-only disclosure would be unreachable by keyboard and would violate the Copywriting Contract's
ban on putting the lift condition in a tooltip). The one `title` attribute in this spec (A6, on the
*disabled* trigger) carries no information absent from that trigger's `aria-label`.

**F10 — Harness wiring (D-04).** Three sub-requirements, all mandatory. The capture extends the
existing harness structurally — no new runner, no new tooling, `@axe-core/puppeteer` stays pinned at
`4.11.3` (`pinned-deps.test.ts` guards this), and axe violations in the opened-drawer state are
baselined at exact integer counts with no tolerance band per the harness's D-06 posture.

- **F10a — an interaction step, not a `routes.json` entry.** `routes.json` entries are
  `{slug, path, contentMarker}` only (verified: `run-a11y.mjs:153` destructures exactly those three)
  — there is no interaction hook, so a new route entry would render `/findings` with the drawer
  **closed** and baseline the wrong DOM. The harness must gain an optional per-route interaction step
  (click the first row's `Storyline` trigger, await the `SheetContent`) that runs before
  `AxePuppeteer`, producing its own variant-aware baseline file per the existing D-15/D-16
  `baseline-{slug}-{variant}.json` convention.
- **F10b — a fixture handler is required, plus its `HOOK_TARGETS` entry.** `vite.config.ts`'s
  `a11yFixture()` middleware matches by `req.url?.startsWith(...)` and has **no handler for
  `/api/findings/`** (verified: the nine existing prefixes are `/api/scan/latest`, `/api/scans`,
  `/api/trends`, `/api/hardware/vendor-trends`, `/api/hardware/drift`, `/api/compare`,
  `/api/qramm/sessions`, `/api/qramm/questions`, `/api/qramm/profiles`). Unmatched requests 404, so
  without a handler the capture would baseline the **error state (S8)** while appearing to pass —
  precisely the "covered but blind" failure Phase 185's D-14 guard exists to prevent. Add a
  `/api/findings` fixture handler returning a fully-populated S1 storyline payload, **and** add the
  storyline hook to `fixture-coverage.test.ts`'s `HOOK_TARGETS` list — that list is hand-maintained
  at three entries (`useHardwareDrift`, `useVendorPqcTrends`, `useCompareData`) and will **not**
  auto-detect the new hook.
- **F10c — the non-default variants do not open the drawer.** Every route carries `-default`,
  `-empty`, and `-loading` baselines. The `empty` variant of `/findings` renders `EmptyStateCard`
  (`findings.tsx:117-121`) and the `loading` variant renders `FindingsSkeleton`
  (`findings.tsx:114`) — neither has table rows, so there is no trigger to click and no drawer to
  capture. The interaction step must therefore be a **no-op under `VITE_A11Y_FIXTURE_VARIANT` in
  (`empty`, `loading`)**, and those two baselines stay exactly as they are today (drawer-closed page
  state). The drawer's opened-state baseline exists for the `default` variant only. Skipping must be
  an explicit, logged no-op — not a silent failure to find the selector, which would be
  indistinguishable from the trigger being broken.

## Type Contract

Every nullable numeric and nullable string crossing the API boundary for this feature is declared
**required-and-nullable** (`field: T | null`), never optional (`field?: T`). 201-UI-E2 raised exactly
this: `?:` admits `undefined` in addition to `null`, so the type system stops being able to enforce
the honest-absence contract and a missing field silently becomes a third state.

**New TS interface in `src/dashboard/src/types/api.ts`** (field names are Claude's discretion per
D-01's discretion grant; the *shape rule* is not):

```ts
export interface FindingStoryline {
  finding_id: number
  narrative: string | null
  quantum_impact: string | null
  remediation_guidance: string | null
  theme_slug: string | null
  theme_title: string | null
  theme_score_lift: number | null
  theme_finding_count: number | null
  theme_closed_count: number | null
  finding_position: number | null
}
```

**No `?:` anywhere in this interface.** Any field the backend may omit must be emitted as explicit
`null` by the Pydantic response model so the TS type is honest. The Pydantic mirror uses
`Optional[...] = None` with the field always serialised (not `exclude_none`).

Note the independence this shape enforces: `theme_score_lift`, `theme_finding_count`,
`theme_closed_count`, and `finding_position` are four separately-nullable fields, which is what makes
states S3/S4/S5 distinguishable at the type level rather than collapsed into one "attribution
missing" flag.

**Required change to the existing type:** `FindingItem.id` is currently `id?: number`
(`types/api.ts:46`). It becomes `id: number | null`. It is the fetch key for the entire feature, so
an `undefined`-vs-`null` ambiguity here is the difference between "no id" and "field absent" at the
exact point the A6 disabled-trigger decision is made. Existing test fixtures constructing
`FindingItem` literals must add `id`. This is a deliberate, in-scope correction of the 201-UI-E2
class, not scope creep.

**Guard style:** all null checks use `!= null` (catches both `null` and `undefined` during the
transition), matching the existing convention at `roadmap.tsx:307` and `print.tsx:204`. Do not use
truthiness (`if (theme_score_lift)`) on any numeric — it would treat a legitimate `0` as absence,
which is the inverse of this codebase's contract.

## Responsive Contract

**Drawer width.** Replace the inline `style={{ width: 480 }}` at `findings.tsx:219` with utility
classes on `SheetContent`: `className="w-full sm:w-[480px] sm:max-w-[480px]"`. The inline style
currently overrides `sheetVariants`' `w-3/4 sm:max-w-sm`, so on a 375px-wide viewport the drawer is
480px and overflows horizontally. With the classes above: below the `sm` breakpoint (640px) the
drawer is full-width; at and above `sm` it is a fixed 480px right-side panel. `480` is a multiple of
4 and is the only width literal this phase introduces.

**Vertical scrolling.** `SheetContent` becomes `flex flex-col` with:

- `SheetHeader` (title + description + the Close button) fixed at the top, not scrolling.
- The body region `flex-1 overflow-y-auto min-h-0`, holding the badge row, Description, Remediation, Quantum Context, Storyline, and the attribution panel.

Long narrative scrolls **inside that body region only**. The page body must not scroll while the
drawer is open (Radix already applies `overflow: hidden` to `document.body` via the Dialog primitive
— do not defeat it), and the findings table behind the overlay must not scroll.

**Horizontal overflow.** Zero horizontal scrolling at any viewport width. Long single tokens
(hostnames, URLs in narrative text) use `break-words`; the attribution panel's sentences wrap
normally. **No table, no `<pre>`, no fixed-width grid inside the drawer** — the position and closure
data are sentences, not a table, specifically so there is no wide content to horizontally scroll and
no per-row points column to invite the forbidden per-finding reading.

**Narrow-viewport wrapping.** The attribution lift sentence must wrap gracefully with the accented
`+N` glyph and its condition clause on different visual lines — which is fine, and is why Invariant
1 is specified as a DOM-structure rule (one paragraph, no intervening block element) rather than a
visual one-line rule. Verify at 375px that `+N` and `when all N findings…` remain in the same `<p>`.

**Touch targets.** The `Storyline` trigger at `size="sm"` (`h-8` = 32px in the vendored `Button`) is
below the 44px comfortable touch minimum. The dashboard is a desktop operator surface (the findings
table's 7 existing columns, filter row, and pagination already assume a wide pointer-driven
viewport) and `size="sm"` matches the existing pagination buttons at `findings.tsx:211-212`, so
consistency wins here. **Assumption — see A3 below.**
