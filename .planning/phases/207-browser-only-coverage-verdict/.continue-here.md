## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Duplicate subagent dispatch after an interrupt | The orchestrator saw no Wave-3 commits after an operator Ctrl+C, concluded the executor was dead, and launched a second one. Both ran ~26 min concurrently against the same tree and branch: interleaved edits, one `git add` swept the other's uncommitted work, stress loops fought over the Chromium cache the other was moving aside, and two phantom "intermittent failures" were produced. | blocking | `ListAgents` before any replacement dispatch; `TaskStop` the old agent first. Treat a missing completion notification as "still running", never as "dead". |
| A claim outrunning its evidence | The real damage this session was never broken code — it was records asserting more than they proved. A docstring claimed a "no-truncation proof" the test could not deliver (W-02); a commit message said "this weakens nothing" while the in-code comment retracted it (W-04); a commit message described tests it did not contain (W-07); NODE-EVIDENCE quoted a skip string a later commit had deleted (W-11). | blocking | Every claim gets a mechanical check, not prose. For each assertion, name the state of the world that makes it FAIL — if you cannot, it is a finding. Red-proof before believing green. |
| Fixing a finding by weakening the claim | The cheap resolution to "this test proves less than it says" is to soften the docstring. That makes the finding vanish and the coverage gap permanent. | advisory | Strengthen the test to earn the claim. W-02 was closed by adding per-pillar VALUE assertions, not by editing prose. |
| Deriving an expected value from the same source as the actual value | W-02's root cause: the six pillar labels are static template text compared against a template that always emits them, so the assertion could not detect missing data. | advisory | Hand-compute expected literals. Never let both sides of an assertion share a source. |
| Trusting a hand-derived count | The review found a third `networkidle` race site after the review itself reported two. The fix brief listed 7 of 19 findings and the other 12 were silently left open. | advisory | Regenerate occurrence sets from source at run time; treat predicted counts as hypotheses. A count mismatch is a finding, not a failure. |
