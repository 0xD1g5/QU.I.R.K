## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `--resume-scan-id` argv → `_completed_stages` | Operator-supplied scan_run_id, already ISO-validated at run_scan.py:1499-1504; selects which checkpoint rows are trusted as "already done". |
| discovery loop → `scan_checkpoints` table | The new per-batch completion markers. A wrong marker means hosts are never probed. |
| discovery loop → `{output_dir}/.cache/discovery-batch-*.json` | Per-batch result payloads restored verbatim into the inventory on resume. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163-01 | Tampering | per-batch `write_scan_checkpoint` call in the `_chunked` loop | mitigate | HIGHEST severity in the phase — a batch wrongly marked complete silently drops hosts from a client deliverable. Mitigated structurally: `_batch_swept_ok` is set `False` inside the sweep's `except RuntimeError` block, and the write is gated on it. Additionally, the checkpoint alone never causes a skip — the guard also requires a live `load_cache` hit, so a checkpoint without recoverable results falls through and re-probes. Asserted by `test_failed_batch_writes_no_checkpoint_and_loop_continues`, `test_completed_stage_without_cache_hit_reprobes`, and Part B's `test_batch_writes_are_not_gated_on_args_cache`. |
| T-163-02 | Denial of Service | unconditional per-batch `save_cache` writes | accept (LOW) | Payload is a serialized ports list, not raw nmap XML. Bounded by the D-06 720h TTL. Operator documentation of the disk-proportional-to-batch-count characteristic ships in Plan 163-03. |
| T-163-03 | Tampering | cache key `f"discovery-batch-{scan_run_id}-{batch_num}"` → `os.path.join` | accept | Pre-existing trusted-caller convention across the whole project. `scan_run_id` is ISO-validated before reaching this point (run_scan.py:1499-1504); `batch_num` is an internally generated integer. No externally controlled string enters the key. |
| T-163-05 | Spoofing / Tampering | batch-ordinal drift when target scope changes between runs (Pitfall 3) | accept | `discovery:batch-7` is a pure ordinal, not a content hash. If the operator edits CIDRs or `exclude_ips` between the original and resumed run, batch 7 may not be the same host set. This is the SAME assumption the pre-existing stage-level resume system already makes. Documented as an accepted limitation via an in-code comment (Task 2) and an operator-guide note (Plan 163-03). Solving target-drift detection is explicitly out of scope per CONTEXT.md D-01..D-04. |
| T-163-06 | Information Disclosure | discovered host/port inventory written to `{output_dir}/.cache/` on runs where the operator did not pass `--cache` | accept | The same `{output_dir}` already receives the CBOM, the HTML/DOCX report, and the SQLite DB — all containing the identical host/port inventory at higher fidelity. The new files add no disclosure surface beyond what the output directory already holds. Noted in the operator guide alongside T-163-02. |
