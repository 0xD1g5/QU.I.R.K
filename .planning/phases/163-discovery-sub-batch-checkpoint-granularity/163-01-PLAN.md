<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scan process → local SQLite (`scan_checkpoints`) | Durable resume state written by the scanner, read back by a later invocation of the same binary. Local-trust, single-writer. |
| scan process → `{output_dir}/.cache/*.json` | Durable batch result payloads. Local filesystem, operator-owned directory. |
| cached JSON → in-memory `NmapOpenPort` objects | Deserialization boundary: a cache file could be corrupt or hand-edited between runs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163-01 | Tampering | per-batch completion write in the discovery loop | mitigate | Structural, not procedural: the mirror helper's checkpoint/cache write is gated on `_batch_swept_ok`, which the `except RuntimeError` branch sets to `False`. Pinned by `test_failed_batch_writes_no_checkpoint_and_loop_continues` in Task 2 and by the real-DB row-count assertion in Task 3. |
| T-163-02 | Denial of Service | unconditional per-batch `save_cache` writes | accept (LOW) | Each payload is a small serialized ports list, not raw nmap XML. Bounded by the D-06 720h TTL. Operator-facing documentation of the disk-proportional-to-batch-count characteristic is delivered in Plan 163-03. |
| T-163-03 | Tampering | `save_cache`/`load_cache` key → `os.path.join(cdir, f"{key}.json")` | accept | Pre-existing project-wide convention with a trusted-caller contract. The new key is built solely from an already ISO-validated `scan_run_id` and an internally generated integer `batch_num`; no externally controlled input reaches it. |
| T-163-04 | Tampering | `serial_to_open_ports` deserializing a corrupt/edited cache file | mitigate | Defensive `.get()` + explicit `h and p is not None and proto` guard skips malformed items rather than raising or constructing partially-populated `NmapOpenPort` objects. `load_cache` already returns `None` on corrupt JSON (Phase 72 D-18). Pinned by the malformed-item bullet in Task 1's `<behavior>`. |
</threat_model>
